# 공공데이터와 AI 활용 정리 (2026-09-29)

팀원(FE · AI 담당, 보고서 작성) 모두가 같은 사실을 보고 말하려고 적는다. 숫자는 모두 직접 세거나 사이트 · 코드에서 확인한 값이고, 확인하지 못한 것은 따로 적었다.

## 한 줄로

공단 데이터 세 가지(측정 분포 · 처방 기록 · 운동 영상)를 **가정에서 부모와 아이가 매일 10~15분 함께 하는 운동 흐름**으로 잇는다. AI 는 영상을 동작으로 자르고, 처방 말과 영상 이름을 잇고, 비슷한 또래의 처방을 근거로 오늘 한 회를 짜는 데 쓴다. 백분위와 등급은 AI 가 아니라 공식 표와 계산식으로 낸다.

## 기획 명분 — 바꾼다

- **예전:** 「공단 API 에 유소년 운동영상이 없다 → AI 로 새로 만든다」. **사실이 아니다.** 공단 동영상 API 에 유소년 영상 108편이 2022년부터 있다.
- **이제:** 「요즘 아이들은 운동할 시간이 없고, 혼자서는 이어지지 않는다. 그래서 부모와 함께, 집에서, 매일 짧게 하도록 만든다.」 기획서 2.1 문제인식(「아이 혼자서는 지속되지 않는 유소년 운동」)이 이미 이 얘기라 그대로 살린다.
- 기획서에서 뺄 문장(한글 파일 기준 문단): 「공단 API 에 없는 유소년 운동영상 메타데이터를 AI 라벨링으로 새로 구축」, 「국민체력100 운동 동영상 API 는 전부 성인을 대상으로 하며」, 「공단 API 에 없는 유소년 운동영상 라벨 데이터셋을 구축」, 「국민체력100 공식 앱 · 웹은 … 유소년 영상이 없습니다」, 「유소년 영상 추천은 팀이 새로 구축하는 라벨 데이터 없이는 동작하지 않습니다」.

## 확인한 사실

**처방 기록**
- 원자료 24개 파일(2024.07~2026.07 측정분, 2026-08-27 받음) 모두에 유아기 · 유소년 · 청소년 처방이 있다. 측정 가운데 처방이 있는 비율은 유아기 92% · 유소년 91% · 청소년 96% 이고, 처방이 한 건도 없는 달은 없다.
- 처방은 「준비운동:… / 본운동:… / 정리운동:…」 처럼 **운동 이름만** 있다. 영상 주소는 없다.
- **만 7~10세는 측정이 0건이라 처방도 없다.** 국민체력100 측정 구간이 유아기(48~83개월)와 유소년(만 11~12세)으로 나뉘어 있어서다.
- 사이트의 「체력 측정별 운동처방 데이터」(처방만 떼어 올린 것)는 설명에 연령대를 「유아기, 청소년, 성인, 어르신」 으로 적어 **유소년이 빠져 있다.** 미리보기를 열면 유소년 처방이 있다.
- 2024년 7월보다 앞선 측정분과, 8월 20일 갱신 전 파일의 내용은 확인하지 못했다.

- 한 줄은 영상 속 장면 하나다(`snap_tm` 장면 전환 시각). 영상 한 편으로 보려면 `file_nm` 으로 묶는다. 영상 주소는 `file_url` + `file_nm`(mp4).
- 공단 API 영상은 **한 편에 운동 하나**다. 앱에 넣은 776편은 길이 중앙값 79초(32초~3분 16초)다. 공단 유튜브 영상은 여러 동작을 이어 한 프로그램(수 분~25분)이다.
- 데이터 줄의 마지막 수정일(`job_ymd`)은 2022년 9~11월과 2023년 6~7월(유아기)뿐이다. 2024년 뒤로 바뀐 줄은 없다.
- **앱에 넣은 것은 776편**이다: 성인 362(공통을 성인으로 셈) · 청소년 186 · 어르신 120 · 유소년 108. 뺀 것은 유아기 전부(열리지 않음), 재는 법을 보여 주는 측정 영상, 여러 동작을 이은 프로그램 · 루틴 영상, 그리고 근골격계운동 114편(「어깨 · 무릎 · 허리관련 질환자를 위한 단계별 표준운동」 — 건강한 가족에게 환자 재활 영상을 권하지 않게)이다. 776편 가운데 운동이 아니라고 라벨된 66편과 물속 영상 21편은 표에 두되 후보로 쓰지 않아, 실제 후보는 689편(유소년 107 · 청소년 141 · 성인 340 · 어르신 101)이다.
- 제목 끝 「-1」 「-2」 는 같은 운동의 몇 번째 영상인지라 화면에 내는 이름에서 뗀다(「목 스트레칭-2」 → 「목 스트레칭」). 여러 편이 한 이름으로 묶여 한 회에 같은 운동이 두 번 뽑히지 않는다.

**처방 이름과 영상 이름이 맞는 정도 — 글자 기준** (처방에 나온 횟수 기준, 띄어쓰기 · 문장부호만 빼고 글자가 같은지. 공단 API 영상은 연령대를 가리지 않고 전체와 맞춰 봤다)

|---|---|---|---|---|
| 유아기 | 65% | **17%** | **84%** | **97%** |
| 유소년 | 95% | 95% | 17% | 95% |
| 청소년 | 63% | 63% | 5% | 63% |
| 성인 | 92% | 91% | 7% | 92% |
| 어르신 | 77% | 76% | 9% | 78% |

- 글자가 어긋나는 흔한 경우: 도구 이름(「덤벨 잡고 앉았다 일어서기」 ↔ 「봉 잡고 앉았다 일어서기」), 번호(「앉아서 다리 펴기」 ↔ 「앉아서 다리 펴기-1」), 루틴 이름(「동적 스트레칭 루틴프로그램」).
- 「처방과 영상이 이름으로 100% 맞는다」 고 말하지 않는다. 연령대마다 다르다.
- 이 표는 글자만 맞춰 본 값이라 **앱이 실제로 쓰는 값이 아니다.** 특히 유아기의 17% · 97% 는 유아기가 아닌 공단 영상(공통 등)과 맞은 것까지 친 값이다 — 유아기 API 영상은 열리지 않는다. 앱은 유아기에게 유아기 영상만 준다. 보고서에는 아래 「AI 가 이은 뒤」 값을 쓴다.

**AI 가 이은 뒤, 앱이 실제로 후보로 쓰는 영상 기준** (AI 커밋 `5a3391b` 에서 잰 값. 연령대 · 운동 여부 · 물속 영상을 거른 뒤. 질환자용 근골격계운동 114편을 빼기(`d7f71e1`) 전 890편으로 쟀다 — 성인 · 어르신 값은 다시 재면 조금 낮아질 수 있다)

## AI 가 하는 일 — 보고서에 이렇게 쓴다

1. **영상을 동작으로 자른다.** 공단 유튜브 프로그램 영상 48편의 화면 이름표를 읽어(OCR) 동작 단위 클립 695개로 나눈다. 공단 API 영상은 한 편이 한 동작이라 자를 필요가 없다.
2. **처방 말과 영상 이름을 잇는다.** 글자가 같으면 그대로, 다르면 임베딩(유사도 0.90 이상)으로, 그래도 애매하면 LLM 이 후보 가운데서 고른다. 도구만 다르면 같은 동작으로 보고, 방향이나 움직임이 다르면 잇지 않는다(「아령 앞으로」 ↔ 「아령 뒤로」는 임베딩 점수가 높아도 잇지 않는다). 앱에 넣은 공단 API 영상 776편 가운데 508편이 처방 운동에 이어졌다(글자 같음 443 · 임베딩 26 · LLM 39, AI `9f6e746` 라벨 표). 잇지 못한 영상도 체력요인 · 단계 라벨로 후보에 들지만, 처방에 실제로 나온 동작이 먼저 선다.
3. **그래서 처방 운동 하나에 영상 후보가 여럿 생긴다.** 공단 API 영상과 유튜브 클립이 한 후보 목록에 들어가, 처방 운동 하나당 틀 수 있는 영상이 평균 0.34편에서 1.22편으로 늘었다. 유소년은 처방에 나온 운동 가운데 틀 영상이 있는 비율이 19% 에서 95% 로 올랐다. 공단 API 영상이 열리지 않는 유아기는 유튜브 클립이 채운다(87%).
4. **비슷한 또래의 처방을 근거로 찾는다(검색 증강).** 67만 건 측정의 처방 기록을 연령 · 성별 · 체력요인 단위 근거 4,137개로 묶어, 집에서 잰 우리 아이와 같은 조건의 또래가 받은 처방을 인용한다. 기록이 없는 만 7~10세는 가장 가까운 나이(만 11~12세)로 넓히고 넓혔다고 알린다.
5. **오늘 한 회를 짠다.** 오늘 가능한 시간, 장소, 조용히 하기, 도구 없음, 보호자가 키워 주고 싶은 역량에 맞춰 LLM 이 준비 · 본 · 정리 순서로 짠다. 인용과 금지어 검사를 통과한 것만 보호자에게 제안하고, 보호자가 승인해야 아이 미션이 된다. LLM 이 실패하면 규칙 편성이 대신한다.

**AI 를 쓰지 않는 곳:** 백분위와 등급. 공식 표와 계산식으로만 낸다 — 같은 값이면 늘 같은 결과가 나와야 믿을 수 있다.

**쓰지 말 표현**
- 「공단 API 에 유소년 영상이 없다」, 「유소년 운동영상을 새로 구축했다」
- 「처방과 영상이 이름으로 100% 맞는다」
- 「유아기 처방에 틀 영상이 17% 에서 97% 로 늘었다」 — 글자만 맞춰 본 값이고 앱이 쓰는 값이 아니다(위 표)
- 「공식 기준이 예전 규칙보다 엄격하다」 (종목에 따라 반대다)
- 「보호자가 키워 주고 싶은 역량을 AI 가 반영한다」 — AI 로컬 브랜치(`b070698`)에서 고쳤지만 아직 병합 · 배포 전이다. 배포 중인 AI 는 이 값을 받아서 버린다. 병합 · 배포 뒤에는 써도 된다

## 등급 · 백분위 — 바뀐 것

- **백분위(상위 N%)** 는 AI 의 또래 표(한 살 단위, 표본 30명 미만은 내지 않음)와 AI 계산식으로 낸다. BE 가 쓰던 예전 표(나이 구간표)는 AI 저장소에서 지워진 것이라 걷었다.
- **등급**은 국민체력100 인증서처럼 한 사람에게 하나(1 · 2 · 3등급 · 참가)다. 인증 기준표 1,122줄로, 그 등급이 보는 종목을 모두 재고 모두 넘어야 받는다. 종목마다 붙던 등급은 없앴다. 모자라면 「등급을 매기려면 ○○도 재야 해요」 를 보여 준다. 같은 나이 · 성별 참가자의 등급 비율(원자료 인증 결과)도 함께 보여 준다.
- 3등급 판정에 필요한 **체지방률 · 허리둘레** 입력 칸을 더했다.
- 만 65세 이상은 유연성 · 악력 백분위가 새로 생긴다. 만 7~10세는 또래 비교 없이 잰 기록만 보여 준다.
- 유아기의 공식 이름은 열매 · 꽃 · 새싹 · 씨앗이고 참고용이다. 앱은 1 · 2 · 3등급으로 보여 준다.

## 남은 결정

1. **로컬 브랜치를 언제 올리고 병합할지.** BE `feature/BE-35-launch-readiness`, AI `feature/AI-kspo-video-api` · `docs/contest-name`, FE `feature/FE-qa-two-weeks` · `docs/readme-facts`.
   - 배포는 **BE 와 FE 를 함께 올리고 AI 를 마지막에** 올리길 제안한다. BE 가 새로 내보내는 공단 영상(운동 찾기 · 대체 편성)은 mp4 라 FE 의 mp4 재생(`45693c6`)이 있어야 틀 수 있다. 거꾸로 FE 의 등급 카드 · 심사용 계정 단추는 BE 의 새 응답 · 주소를 쓴다. AI 가 먼저 공단 영상을 고르면, 옛 BE 는 그 영상을 영상 표에서 찾지 못해 유튜브 주소로 내보내고 화면이 틀지 못한다.
   - BE-35 는 마이그레이션 V153~V162 를 담고 있다. 번호 차례대로 병합한다.
2. **공단 유아기 영상이 열리지 않는 것.** 유아기 61편의 mp4 주소가 302 → `/error.html` 로 넘어가 앱에 넣지 못했다. 공단(공공데이터포털 15108846 문의)에 물어볼지, 누가 물을지 정한다. 열리면 AI `make kspo-videos` 로 표를 다시 만들고 BE 는 `kspo_videos_to_sql.py` 로 새 V 파일을 만든다. 그 전까지 유아기는 유튜브 클립만 쓴다.
3. **65세 이상에게 공단 어르신 영상을 함께 쓰는 것.** 예전 팀 결정은 「어르신 전용 영상을 따로 만들지 않고 성인 영상을 똑같이 쓴다」 였다. 이번에 공단 어르신 영상(후보 101편)이 들어와, 65세 이상에게는 어르신 영상을 먼저 세우고 성인 영상을 함께 준다. 성인 영상을 썼다는 알림은 달지 않는다. 이대로 가도 되는지 확인한다.
4. **보고서 문장 교체.** 위 「기획 명분」 의 다섯 문장을 빼고 「AI 가 하는 일」 로 바꿔 쓴다. 누가 언제 한글 파일을 고칠지 정한다. 숫자는 「AI 가 이은 뒤」 표의 값을 쓴다.
5. **FE-117 환영 안내를 병합할지.** 원격 `feature/FE-117-legal-welcome-develop` 의 5커밋(약관 · 개인정보처리방침 · 동의서를 법이 요구하는 틀로 다시 쓰기, 첫 시작 동의 두 줄에 「필수」, 조 번호 검사, 처음 들어올 때 한 번 뜨는 환영 안내와 그 검사)이 develop 에 없다. develop 바로 위에 있어 그대로 병합할 수 있지만, FE `feature/FE-qa-two-weeks` 와 합치면 `src/lib/legal.ts` 에서 충돌이 난다.
